# 整体服务启动流程

本文档说明当前项目的一键启动方式、服务顺序、端口、日志位置和常见排查命令。

## 1. 推荐启动命令

在项目根目录执行：

```bash
./start_all.sh
```

如果是第一次部署，或 `stock-mcp/.venv`、依赖、配置没有准备好，先执行：

```bash
./start_all.sh --setup
```

如果要重启完整服务：

```bash
./start_all.sh restart
```

停止完整服务：

```bash
./start_all.sh stop
```

查看状态：

```bash
./start_all.sh status
```

执行验证：

```bash
./start_all.sh verify
```

查看日志：

```bash
./start_all.sh logs startup
./start_all.sh logs stock-mcp
./start_all.sh logs librechat
./start_all.sh logs nginx
```

> `start_all.sh` 是根目录统一入口；底层实际复用 `deploy/start.sh`、`deploy/stop.sh`、`deploy/verify.sh`，避免维护两套启动逻辑。

## 2. 服务启动顺序

当前完整栈按以下顺序启动：

### 第 0 步：前端构建与 nginx 快速启动

1. 检查 `frontend/dist` 是否存在。
2. 如果不存在，执行前端构建：

   ```bash
   cd frontend
   npm run build
   ```

3. 测试并启动 nginx。
4. nginx 监听统一入口：

   ```text
   http://127.0.0.1:3001
   ```

这样 `/health` 可以尽快响应。

### 第 1 步：基础服务

后台启动或复用以下基础服务：

| 服务 | 端口 | 用途 |
|---|---:|---|
| MongoDB | 27017 | LibreChat 用户、会话、消息存储 |
| Redis | 6379 | LibreChat 缓存/会话辅助 |
| Meilisearch | 7700 | LibreChat 搜索 |
| Clash | 7897 | 可选代理；没有配置时不阻塞启动 |

### 第 2 步：stock-mcp

启动命令由 `deploy/start.sh` 生成，关键环境变量：

```bash
LIBRECHAT_USER_DATA_DIR=<项目根目录>/librechat_user_data
MCP_TRANSPORT=streamable-http
PYTHONPATH=<项目根目录>/stock-mcp
```

Python 使用项目内虚拟环境：

```text
stock-mcp/.venv/bin/python
```

不使用 conda。

stock-mcp 监听：

```text
http://127.0.0.1:9898
```

健康检查：

```bash
curl http://127.0.0.1:9898/health
```

### 第 3 步：LibreChat

在 stock-mcp 健康后再启动 LibreChat。原因是 LibreChat 启动时会初始化 MCP server；如果 stock-mcp 尚未健康，可能出现 MCP tools 数量为 0 的问题。

关键配置：

```bash
CONFIG_PATH=<项目根目录>/LibreChat/config/librechat.stock-mcp.yaml
LIBRECHAT_USER_DATA_DIR=<项目根目录>/librechat_user_data
NODE_ENV=production
```

LibreChat 内部监听：

```text
http://127.0.0.1:3080
```

通过 nginx 访问：

```text
http://127.0.0.1:3001/librechat/
```

### 第 4 步：统一 nginx 入口

nginx 统一暴露 `3001` 端口：

| 路径 | 代理目标 |
|---|---|
| `/` | `frontend/dist` 静态前端 |
| `/librechat/` | LibreChat `127.0.0.1:3080` |
| `/api/v1/files/*` 等 stock API | stock-mcp `127.0.0.1:9898` |
| `/api/agents/*` | LibreChat，避免 SSE 流被转到 stock-mcp |
| `/health` | nginx 本地健康检查 |

## 3. 数据存储位置

LibreChat 的用户、对话、消息存在 MongoDB：

```text
MongoDB: LibreChat database
```

stock-mcp 获取到的数据集不是直接写入 MongoDB collection，而是按用户 ID 写入：

```text
librechat_user_data/<LibreChat用户ObjectId>/dataset/
```

例如：

```text
librechat_user_data/6a4d39c873ceb460e63717df/dataset/苹果近半年股价.csv
librechat_user_data/6a4d39c873ceb460e63717df/dataset/苹果近半年股价.meta.json
```

“我的数据”页面通过 stock-mcp API 查询这些文件，并依赖请求头：

```text
X-User-Id: <LibreChat用户ObjectId>
```

## 4. 端口总览

| 服务 | 端口 | 对外/内部 | 健康检查 |
|---|---:|---|---|
| nginx 主入口 | 3001 | 对外入口 | `curl http://127.0.0.1:3001/health` |
| LibreChat | 3080 | 内部 | `curl http://127.0.0.1:3080/health` |
| stock-mcp | 9898 | 内部/API | `curl http://127.0.0.1:9898/health` |
| MongoDB | 27017 | 内部 | 端口检查 |
| Redis | 6379 | 内部 | 端口检查 |
| Meilisearch | 7700 | 内部 | 端口检查 |
| Clash | 7897 | 可选 | 端口检查 |

所有启动日志在：

```text
deploy/logs/
```

常用日志：

| 日志 | 文件 |
|---|---|
| 总启动日志 | `deploy/logs/startup.log` |
| nginx | `deploy/logs/nginx.log`、`deploy/logs/nginx_error.log` |
| stock-mcp | `deploy/logs/stock-mcp.log` |
| LibreChat | `deploy/logs/librechat.log` |

| Redis | `deploy/logs/redis.log` |
| Meilisearch | `deploy/logs/meilisearch.log` |
| 前端构建 | `deploy/logs/frontend.log` |

使用统一入口查看：

```bash
./start_all.sh logs startup
./start_all.sh logs stock-mcp
./start_all.sh logs librechat
```

## 6. 启动后验证

推荐执行：

```bash
./start_all.sh verify
```

也可以手动验证：

```bash
curl http://127.0.0.1:3001/health
curl http://127.0.0.1:9898/health
curl http://127.0.0.1:3080/health
```

如果要确认某个用户的数据列表可查，例如用户 ID 是 `6a4d39c873ceb460e63717df`：

```bash
curl -H 'X-User-Id: 6a4d39c873ceb460e63717df' \
  http://127.0.0.1:3001/api/v1/files/dataset
```

## 7. 常见问题

### 7.1 “我的数据”页面没有数据

优先检查浏览器 localStorage 是否有：

```text
librechat_auth=true
librechat_user={... id: "<ObjectId>" ...}
librechat_token=<token>
```

再检查 API 是否能返回数据：

```bash
curl -H 'X-User-Id: <用户ObjectId>' \
  http://127.0.0.1:3001/api/v1/files/dataset
```

如果 API 有数据但页面不显示，通常是前端认证状态没有同步到 `librechat_user`。

### 7.2 LibreChat 能聊天但 MCP 没工具

先确认 stock-mcp 健康：

```bash
curl http://127.0.0.1:9898/health
```

然后重启完整栈：

```bash
./start_all.sh restart
```

原因：LibreChat 启动时会初始化 MCP server，stock-mcp 必须先健康。

### 7.3 端口占用

查看状态：

```bash
./start_all.sh status
```

停止后重启：

```bash
./start_all.sh stop
./start_all.sh
```

### 7.4 前端还是旧页面或旧 JS

nginx 对静态资源有缓存。浏览器执行硬刷新：

```text
macOS: Cmd + Shift + R
Windows/Linux: Ctrl + Shift + R
```

### 7.5 stock-mcp Python 环境缺失

如果看到：

```text
stock-mcp/.venv/bin/python 不存在
```

执行：

```bash
./start_all.sh --setup
```

或者单独运行：

```bash
bash deploy/setup.sh
```
